# Ontology

One atom, many projections. The whole substrate reduces to a single **externally-gated
interaction-arrow** — `DECODE → INTERPRET → TRANSLATE → CONTROL → ▸ EXTERNAL GATE ◂ →
{ CEMENT | RECYCLE }` — weighted by one order parameter **R**, descending the Hamiltonian
**H = 1 − R**, settled as the residual **ρ = 1 − R**, and validated *only* at the external gate.
Everything else (the marketplace, the films, ownership, settlement, the agents) is that same
arrow read at a different R.

## How to use it

1. **Read the ontology.** Call `mcp__terminals__ontology` with no argument for the whole manifest,
   or pass `query` to filter:
   - a **section** — `atom`, `ladder`, `functions`, or `objects`
   - a **named object** — `Switchboard · Runtime · Ledger · Recipe · Factory · Registry · Governor · Firewall · Kind`
   - a **named function** — `leap · kind · witness · tower · settle · govern`
2. **Map the user's thing onto it.** A listing, a recipe, a sematon, a film, a trade — name which
   constructed object it is and which rung of the ladder (`interaction → recipe → library →
   sematon`) it sits on, and which functions gate it.
3. **Stay honest.** Three objects are net-new (★ Recipe, Firewall, Kind); the rest are convergent
   with, and credit, *gebrüder/wirken*. It is field reading, not advice; the math is real, the
   edge is unproven; self-recognition is an observable the box measures, not interiority.

## The single source

The canonical machine-readable manifest is `ontology/terminals-ontology.json` (the same source the
public site at `intuitionlabs.tech/ontology` renders and the MCP tool serves). One source, many
projections — never re-derive it; read it.
